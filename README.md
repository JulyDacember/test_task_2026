**Результаты первичного анализа кода для выявления возможных проблемных мест, замедляющих работу:**

| Файл | Проблема | Последствие |
|---|---|---|
| `main.py` | Запрос к БД выполняется для каждого покупателя | Большое количество SQL-запросов |
| `main.py` | `commit()` после каждого покупателя | Лишние транзакционные накладные расходы |
| `abstract_customer.py` | `commit()` внутри `create_or_update_lead()` | Много отдельных транзакций |
| `main.py` | Повторное чтение всей таблицы при очистке | Дополнительная нагрузка на БД и память |
| `main.py` | Ошибки обработки сделок перехватываются, но синхронизация продолжается | Очистка может запуститься после неудачной выгрузки |
| `main.py` | При объединении записей `lead_action()` возвращает `None` | Возникает ошибка при обращении к `abc_customer.id` |
| `abstract_customer.py` | Новый объект добавляется в сессию без `flush()` | Его `id` может быть ещё не получен при заполнении `ids_map` |
| `main.py` | Ошибка в фильтрации вложенных сущностей | Некорректная очистка данных |

Для прогона был написан генератор тестовых данных. Типы сгенирированных данных:
| Тип данных | Количество |
|---|---:|
| Покупатели | 1 000 |
| Сделки | 2 500 |
| Покупатели без логина | 50 |
| Сделки без логина | 100 |
| Сделки с логином существующего покупателя | 1 500 |
| Сделки с неизвестным логином | 500 |
| Сделки с неоднозначным логином | 100 |
| Остальные сделки | 300 |

Также были написаны 11 тестовых сценариев `test_business_rules.py`. При первом зпуске пройдено 8 тестов, 3 теста провалено. 

1. Тест № 7 объединение записей
test_07_conflicting_matches_merge_into_lead_record ... FAIL

AssertionError: unexpectedly None

Что проверяла: сделка уже существует в одной записи, а логин указывает на другую запись с покупателем. По заданию нужно объединить данные и оставить запись, найденную по ID сделки.

Что происходит: lead_action() выполняет объединение, но не возвращает итоговый объект. В результате тест получает None.

Это подтверждает дефект исходной реализации. Нужно исправить возврат объекта после объединения.

2. Тест № 10 удаление вложенных сущностей
test_10_full_sync_removes_missing_and_marked_entities ... FAIL

AssertionError: Lists differ: [] != [101]

Что проверяла: после фильтрации должна остаться сделка с ID 101, а сделка с названием «Сделка удалить» должна исчезнуть.

Что происходит: после вызова filter_merge_abstract_customer() список сделок оказался пустым.

Вероятная причина это ошибка в логике фильтрации вложенных сущностей. Нужно проверить, как функция использует список актуальных ID и как формирует новый JSON-массив.

3. Тест № 11 прерывание синхронизации
test_11_interrupted_collection_does_not_run_cleanup ... FAIL

Что проверяла: если во время обработки сделки возникает исключение, уже сохранённые записи нельзя удалять.

Что происходит: исключение перехватывается внутри collect_leads_customers(), после чего выполнение продолжается. В итоге запускается очистка, и ранее существовавшая запись удаляется.

Это наиболее серьёзная из трёх ошибок: неудачная синхронизация может привести к потере данных.
